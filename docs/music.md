# Музыка: полка и свой трек

## Свой трек — как это устроено

«Музыка: библиотека треков… и возможность добавить свою» (doc-03). Своя — это аудиофайл, который
организатор заливает **тем же путём, что и материал**: заявка, подписанные куски, «загружено».
Байты в API не приходят и здесь.

1. `POST /memories/:memoryId/music` — заводится запись `music_uploads` в статусе `pending_upload`,
   в ответ — подписанные ссылки на куски и ключ будущего объекта.
2. Приложение шлёт `PUT` на каждую ссылку и запоминает `ETag` ответов.
3. `POST /memories/:memoryId/music/:trackId/complete` — API собирает объект, переводит запись в
   `ready` и возвращает ключ.
4. Этот ключ приложение кладёт в `music_tracks` при заказе ролика — рядом с id треков с полки.

Своя таблица, а не третий `kind` в `media_items`: трек — не материал воспоминания. В галерею он не
попадает, в те самые «три готовых файла» не считается, превью с него никто не снимает. У записи
всего два состояния, `pending_upload` и `ready`: воркер трек не обрабатывает — только скачивает.

Ссылок **не перевыдаём**: трек — небольшой файл, а час (`R2_UPLOAD_TTL_SECONDS`) — долгий срок.
Протухли — заводится новая заявка. Размер трека в счётчики воспоминания (`storage_bytes`,
`media_count`) не идёт: те считают галерею, а вернуть их назад некому — трек не удаляется.
Потолок на файл общий с медиа (`MEDIA_MAX_FILE_BYTES`).

## `POST /memories/:memoryId/music`

За `app.authenticate` + `app.requireMembership`. Только **`organizer`**: трек — это пожелание к
ролику, а ролик заказывает он (`contributor` и `viewer` получают `403 {"error":"forbidden"}`).

```
{"size_bytes": 4194304}
```

```
201 Created
{"id":"…","status":"pending_upload",
 "upload":{"key":"music/…","upload_id":"…","part_size":8388608,
           "parts":[{"part_number":1,"url":"http://…&X-Amz-Signature=…"}],
           "expires_at":"2026-09-03T12:00:00.000Z"}}
```

Ключ — по id записи, и он приходит в ответе: собирать его на клиенте не нужно, и именно он потом
уходит в `music_tracks`.

| Ответ | Тело                                                        | Когда                          |
|-------|-------------------------------------------------------------|--------------------------------|
| `403` | `{"error":"forbidden"}`                                      | участник, но не организатор    |
| `413` | `{"error":"file is too large","limit_bytes":1073741824}`     | файл больше потолка            |
| `503` | `{"error":"storage not configured"}`                         | не заданы `R2_*`               |

Отказ по потолку — **до** записи: ни строки, ни загрузки в хранилище не остаётся.

## `POST /memories/:memoryId/music/:trackId/complete`

Там же. Доделать загрузку может только тот, кто её начал: это не про роль, а про владение. Куски —
все, что были отправлены, с их `ETag`, тело — как у медиа-колбэка.

```
200 OK
{"id":"…","status":"ready","key":"music/…"}
```

**Повторный вызов безопасен**: трек уже `ready` — приходит тот же ответ, второй записи не
заводится.

Записывается **тот размер, который хранилище реально держит**. Объекта в хранилище нет — `409
{"error":"the upload is not in storage"}`, запись остаётся `pending_upload`, загрузку можно
доделать. Объект оказался больше потолка (заявили мало, прислали много) — `413`, и тогда уходят и
запись, и объект: подписанный кусок своей длины не несёт, и поймать это можно только здесь.

Чужая запись, запись из другого воспоминания, несуществующая и кривой `trackId` — общий
`404 {"error":"not found"}`. Не заданы `R2_*` — `503 {"error":"storage not configured"}`.

## `GET /music/tracks/:trackId`

За одним `app.authenticate`. «Послушать» на экране «Под что монтировать»: подписанная ссылка на
трек **с полки** — тот самый файл, под который смонтируется ролик, до того как ролик заказан.

```
200 OK
{"url":"http://…&X-Amz-Signature=…"}
```

Вне `/memories/:memoryId` намеренно: полка одна на весь продукт, одни и те же пять треков для всех,
и проверять тут нечего, кроме того, что человек вошёл — ни членства, ни роли, ни воспоминания.
Ключ — `tracks/<id>.mp3`, файлы туда выкладывает воркер (`python -m montage tracks`). Ссылка живёт
`R2_DOWNLOAD_TTL_SECONDS`, и байты идут из хранилища напрямую — как у медиа.

`trackId` — один из пяти, тем же списком, которым проверяются id в `music_tracks` заказа: чего нельзя
заказать, того нельзя и послушать. Любой другой — `404 {"error":"not found"}` (не `400`: трека
попросту нет). Не заданы `R2_*` — `503 {"error":"storage not configured"}`.
