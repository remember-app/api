# remember-api

Бэкенд-API продукта **Remember** — единственная точка входа для мобильного приложения.
TypeScript + [Fastify](https://fastify.dev/) + Postgres.

Сейчас здесь скелет (m-7 Foundation), аккаунт целиком (m-3 Accounts), воспоминания с участниками
и медиа целиком: health-эндпоинт, подключение к базе, миграции, аутентификация запроса,
ник и управление сессиями, права на воспоминание, подписанные ссылки на загрузку в хранилище,
галерея воспоминания, скачивание оригиналов — одного файла и всей галереи — и удаление медиа,
поштучно и каскадом при уходе участника. Остальные сущности приходят со своими фичами.

Продуктовая плоскость — в корневом репозитории (`backlog/`). Архитектурные решения этого
сервиса — здесь, в `docs/`.

Поднять с нуля — [docs/running.md](docs/running.md).

## Где что лежит

```
src/app.ts            Fastify-приложение и маршруты (без сети — тестируется через inject)
src/server.ts         точка входа: проверить базу, слушать порт
src/db.ts             клиент Postgres из DATABASE_URL
src/auth/session.ts   выпуск, проверка с продлением и отзыв сессий
src/auth/email.ts     вход по коду на email: выпуск кода, попытки, проверка
src/auth/mail.ts      отправка письма с кодом по SMTP (nodemailer)
src/auth/providers.ts проверка id-токенов Apple и Google (jose, JWKS)
src/auth/social.ts    маршруты входа через Apple и Google и список включённых способов входа
src/auth/plugin.ts    декоратор app.authenticate и маршруты входа
src/auth/identity.ts  соглашение, ник, язык, «даты между днями», поиск по нику, сессии
src/auth/config.ts    сроки и лимиты из окружения, с проверкой значений
src/auth/testing.ts   общая оснастка тестов (приложение с логом, вход, уборка)
src/contacts/contacts.ts  свой список контактов: сохранить по нику, список, удалить
src/memories/plugin.ts    декоратор app.requireMembership и маршруты воспоминаний
src/memories/members.ts   участники: приглашения, роли, статус вклада, удаление
src/memories/removal.ts   удаление воспоминания целиком, вместе со всем, что на нём висит
src/memories/push.ts      пуш-токены и отправка уведомлений
src/media/upload.ts   приём загрузки: заявка, повторная ссылка, колбэк «загружено»
src/media/gallery.ts  галерея, удаление медиа и общий каскад (счётчики, jobs, ключи R2)
src/media/frame.ts    сведения об одном кадре: кто принёс, файл, камера, место, ролики; правка хозяином
src/media/labels.ts   лейблы воспоминания: список, запись, правило видимости и правило прав
src/media/r2.ts       хранилище: multipart и подписанные ссылки; драйвер s3 (MinIO, S3-совместимые) по умолчанию
src/media/gcs.ts      драйвер google: Google Cloud Storage по JSON-ключу служебной учётки, под префиксом
src/media/config.ts   лимиты и сроки ссылок из окружения
src/montages/montages.ts  маршруты ролика: заказ, итог, список, повтор, имя, удаление (и общее удаление роликов)
src/montages/order.ts     что клиент может попросить и потянет ли это воспоминание
src/montages/material.ts  что остаётся заказу от материала и на какую длину его хватает
src/montages/summary.ts   «итог перед монтажом»: числа до заказа и оценка ожидания
src/montages/row.ts       строка `montages` и словарь, которым написаны её `params`
src/montages/view.ts      ролик наружу: строка без ключей, кто заказал, подписанные ссылки, «Ролик на 1:00» без имени
src/montages/watched.ts   «посмотрели»: отметка с экрана готового ролика и кто отмечен
src/montages/ready.ts     стук воркера о готовом ролике, за общим секретом
src/montages/journal.ts   журнал сборки: чтение порциями, смотрящие, шкала этапов
src/montages/templates.ts шесть готовых роликов — тот же заказ, заполненный заранее
src/montages/music.ts     полка из десяти треков и свой трек организатора
src/privacy/privacy.ts    GET /privacy — публичная страница политики конфиденциальности, текст в этом же файле
scripts/migrate.ts    запуск postgrator и таблица jobs из montage
scripts/storage-check.ts  живой контроль хранилища: все обращения api на бакете для проверок
migrations/           .sql-миграции
Dockerfile            боевой образ; .gitlab-ci.yml на пуш в dev собирает его и выкатывает на dev
docs/                 как поднять, что обещает каждый маршрут и как это проверяется
```

## Что читать

- [docs/running.md](docs/running.md) — что нужно, как поднять, окружение, миграции, команды.
- [docs/testing.md](docs/testing.md) — как гонять тесты и что они пишут в базу.

Контракты маршрутов — по файлу на семью:

- [docs/auth.md](docs/auth.md) — вход, профиль и его настройки (язык, «даты между днями» —
  `dates_between_days`, меняется `POST /me/dates-between-days`), ник, контакты, сессии и проверки
  прав.
- [docs/memories.md](docs/memories.md) — воспоминания, участники, приглашения, статус вклада.
- [docs/media.md](docs/media.md) — загрузка, галерея, сведения о кадре, скачивание, лейблы.
- [docs/montages.md](docs/montages.md) — ролики: шаблоны, заказ, итог, список, повтор, имя,
  удаление, «посмотрели».
- [docs/journal.md](docs/journal.md) — журнал монтажа: как читается и что пишет воркер.
- [docs/music.md](docs/music.md) — полка из десяти треков и свой трек организатора.
- [docs/push.md](docs/push.md) — пуш-токены и уведомления.
